Add a `ChannelMonitorUpdateStep` for tracking that we've actually
omitted this event.

    - if we got an update after a force closed, it's allowed to be a

## ChannelMonitor: track user-processed payment claims

- Only for closed channels

## Add EventCompletionAction::InboundPaymentClaimedChannelMonitorUpdate

- Just adds the event, no handling
- `EventCompletionAction`: these events just report that a user has
  handled an event so that we can appropriately react. We'll only have
  duplicates if we crash before handling the completion action.

## Prevent redundant PaymentClaimeds for closed channels

- `get_stored_preimages`:
  - Previously just returned all preimages
  - Now we filter out any that are in our `inbound_payments_claimed`
- `handle_monitor_update_completion_actions`:
  - When we have a `PaymentClaimed`
  - And we have a `pending_claiming_payments` entry:
    - Create a `PaymentClaimed` event
    - Decide on our `action`:
      - If we have `durable_preimage_channel`:
        - Check whether the channel is closed
        - If it is `InboundPaymentClaimedChannelMonitorUpdate`
        - Otherwise `ReleaseRAAChannelMonitorUpdate`
      - If no `durable_preimage_channel`: `None` action

- Create a `(PaymentClaimed, action)`:
  - Only pushes into `pending_events` if we haven't got this entry

Q: what is `durable_preimage_channel`?
- We pick one preimage to block monitor update on the event to make
  sure that the channel doesn't progress and remove the preimage before
  the user has handled the event
- It's only an `Option` because it wasn't always set.
-> Fix kinda relies on which channel we pick for `durable_preimage_channel`
