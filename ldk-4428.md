# Zero Reserve Channels

There is a spec feature: https://github.com/lightning/bolts/pull/1140
- Advertises that you allow your peers to disable the channel reserve
  on their side (ie, I accept that you don't want a reserve).
- "May lift the same requirement in response"
  -> I'm not sure what this means.

Summary:
- May set `channel_reserve_satoshis` to 0 in `open_channel` if the
  peer supports `option_zero_reserve`
- There's a "be nice back" suggestion that you do the same.

`for_splice`:

TxBuilder:
- `check_no_outputs`:
  - Subtract our fee off of the fee-paying party's balance
  - Get the dust limit for the person who will broadcast this tx
  - If *both* outputs are below this balance *and* we don't have any
    non-dust HTLCs, error out

- `get_next_commitment_stats`:
  - Check that we actually have outputs on our commitment
  - Get the commitment fee for "one extra" HTLC (as before), we know
    we'll have an output here because we are adding a non-dust htlc

`validate_update_add_htlc`:
- We move the `get_next_local_commitment_stats` out of the
  `funding.is_outbound` branch.

`adjust_boundaries_if_max_dust_htlc_produces_no_output`:
- Gets our balances without fees based on who's paying the chain fees
- `min_non_dust_htlc_sat`:
  - If our commit, we add the timeout fee (because we'd timeout)
  - If their commit, we add the success fee (because they'd claim)
- `max_non_dust_htlc_msat` is the minimum less one (this is the largest
  dust htlc we can make)
- If adding a large dust htlc would leave us with no outputs:
  - If we can add non-dust htlcs:
    - The smallest htlc we allow is our htlc minimum on the channel, or
      the non-smallest dust htlc we allow if it's more than that
    - We do not allow dust htlcs, because we won't have any outputs on
      the commitment.
  - If can only add dust htlcs (cause our balance is low):
    - We need to only allow adding a dust htlc that won't trim our
      commitment
    - Or allow adding a non-dust remote htlc that would add an output
