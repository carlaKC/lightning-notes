# RAAMonitorUpdateBlockingAction not applied to downstream channels

We use `RAAMonitorUpdateBlockingAction` to block the _outbound_ channel
on the inbound channel monitor being persisted, so that we can't
progress our outbound channel to the point where we've forgotten about
the preimage (because if we go down then, we've forgotten it).

This is currently added in `update_fulfill_htlc`, based on the source
of the HTLC being `PreviousHopData` or `TrampolineForward`. This commit
would move it into `claim_funds_from_htlc_forward_hop`.
